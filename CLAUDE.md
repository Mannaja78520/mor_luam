# mor_luam — source map

Single-wheel steer-drive robot. ESP32 firmware (PlatformIO, micro-ROS over Wi-Fi,
own web app, OTA) + ROS 2 Jazzy nodes on the PC + Docker tooling for Windows.
Read this file first; open only the files the task needs.

## Commands (Windows, from the repo root)

```
docker\mor_luam.bat fw-build             build -> firmware\firmware_out\ (also regenerates WebPage.h)
docker\mor_luam.bat fw-ota -Host <IP>    flash over Wi-Fi (password: env MORLUAM_OTA_PASS or prompt)
docker\mor_luam.bat fw-flash -Port COM9  first flash over USB (CP210x shows as COM9 on this PC)
docker\mor_luam.bat fw-test              PC tests
docker\mor_luam.bat web-mock             page on http://localhost:8000 with a fake robot
node firmware\web\test_simulation.cjs   offline browser planner tests; no motor commands
docker\mor_luam.bat find                 robots on this Wi-Fi
docker\mor_luam.bat wifi | logs | topics | run <prog> | shell | stop     ROS side
```

## Facts that are easy to get wrong

- ONE motor: one direction drives the wheel, the other steers it. So it steers one way only and
  can NOT steer while it drives: course errors are fixed by stopping and re-aiming
  (`algorithm/FinalApproach.h`), never by steering on the move.
- The wheel steers ONE way only: COUNTER-clockwise seen from above, so the measured angle INcreases (STEER_SENSE +1, zero 138.6 deg; verified 2026-10-08 by driving forward/left with the owner watching). `cwErrorDeg` = `(target - current) mod 360` ("in the steering direction"); steering test 7/7. The old STEER_SENSE -1 swapped left/right.
  `phi = cwErrorDeg(bearing, wheelHeading)` = how far the wheel must still turn.
- World frame: x forward at the last pose reset, y left, angles CCW (atan2).
- ROS_DOMAIN_ID is 10 on both sides. Default Wi-Fi is the PC hotspot (agent = gateway 192.168.137.1).
- ROS feedback is reliable QoS (PC nodes subscribe reliable); publishers don't wait for ACKs
  (`rmw_uros_set_publisher_session_timeout(..., 0)`), stream history 16 (`firmware/microros.meta`).
  Changing `microros.meta` needs `docker\mor_luam.bat fw-clean-ros` then `fw-build`.
- A web route is intended to stop after 3 s without heartbeat. Any open robot page can keep it alive; the clean live lost-heartbeat retry is still pending (see `docs/testing.md`).
- No wired emergency-switch input or ground-contact sensor exists. Status shows `hardwareEstop: not-wired` and `groundContact: unknown`; missing motor feedback cannot identify the cause.
- The browser simulator sends no motor commands. Its constant-speed model does not measure slip, battery drop, shaking or physical stop distance.
- OTA and pose reset are refused while the robot moves.
- Wi-Fi passwords ARE shown on the robot's page (user's choice); keep them out of chat and git.
- Keep HTTP replies small (a few KB). AsyncResponseStream grows its buffer by each write's bytes
  (O(n^2) copying: a 12 KB reply reset the ESP32 by watchdog), and a ~6 KB reply never arrived even
  pre-sized. Split big data into pages (see `/api/demo/series?run=i`); `reply()` reserves the String once.
