# เปรียบเทียบ Direct / Detour: ระยะรวม 2 เมตร แบ่ง 7 ช่วง

เพิ่มวันที่ 27 ตุลาคม 2026 ตามคำขอให้หุ่นเดินไกลขึ้นและเห็นจังหวะเลี้ยวต่างกันชัด
ใช้กล่อง **เดโม 3 / 4 ครั้ง → ทดสอบ 3 รอบ** บนหน้าเว็บเดิม

**สถานะการเผยแพร่:** ผู้ใช้ขอให้อัปเอกสารขึ้น Git ก่อน โค้ดฟีเจอร์ใหม่นี้ยังเก็บเป็นการแก้ไข
ในเครื่องและยังไม่ได้ push พร้อมเอกสาร เฟิร์มแวร์ที่ติดตั้งบนหุ่นวันที่ 27 ตุลาคมรองรับ
`2.00 m / 7 ช่วง` แล้ว แต่ยังไม่ได้วิ่งทดสอบจริง และการตรวจเว็บบนหุ่นยังพบการโหลดค้าง
บางครั้ง เวอร์ชันโค้ดบน Git ก่อนเผยแพร่ฟีเจอร์นี้ยังจำกัดเป้าเดโม 1 เมตรและไม่มี `demoSegments`
ดูรายละเอียดงานที่ค้างใน [Codex V3](../HANDOFF_MORLUAM_CODEX_V3.md)

## ระยะ 2 เมตรหมายถึงอะไร

- ขาไปมี 7 จุดให้ผ่าน ระยะเส้นตรงเชื่อมจุดแต่ละช่วงเท่ากับ `2 / 7` ≈ **0.286 m**
- ผลรวม 7 ช่วงคือ **2.00 m** ไม่ใช่ช่วงละ 2 เมตร และไม่ใช่เป้าเส้นตรงห่าง 2 เมตร
- แต่ละช่วงเยื้องขวาจากทิศของช่วงก่อน 6° เป็นแนวโค้งอ่อน ๆ ไปด้านหน้าและขวา
- ทั้งสองวิธีผ่านจุดชุดเดียวกันในกรอบเริ่มของแต่ละ run และใช้ความเร็ว/เกณฑ์ถึงจุดเดียวกัน
- Detour อาจขับอ้อมระหว่างจุด จึงมีระยะขับจริงมากกว่า 2 เมตรได้
- หลังถึงจุดสุดท้าย รอ 5 s แล้วกลับจุดเริ่มอีกประมาณ **1.96 m** ขากลับไม่รวมในเวลาเปรียบเทียบ
- 3 รอบ = Direct และ Detour อย่างละ 3 ครั้ง รวม **6 runs** จึงต้องเผื่อเวลารวมและระยะขากลับด้วย

## ทำไมไม่ใช้เป้าจุดเดียวห่าง 2 เมตร

ที่ความเร็วขับ 0.03 m/s, ความเร็วเลี้ยวตามแบบจำลอง 35°/s และมุมเยื้อง 6°
planner ของ Detour จะเลือกทางเดียวกับ Direct สำหรับเป้าจุดเดียวห่าง 2 เมตร
การแบ่งช่วงสั้นทำให้บางช่วงใช้การอ้อมจริง โดยไม่บังคับเส้นทางอ้อมที่ algorithm เห็นว่าช้ากว่า

แบบจำลองอุดมคติของเส้นทาง 7 ช่วงให้ค่าต่อไปนี้:

| ค่า | Direct | Detour |
|---|---:|---:|
| เวลาขาไปตามแบบจำลอง | 137.82 s | 110.52 s |
| ระยะขับขาไปตามแบบจำลอง | 2.00 m | 2.17 m |
| มุมที่ล้อหมุนรวม | 2,478° | ประมาณ 1,291° |
| ช่วงที่ planner เลือกอ้อม | 0 | 4 |

นี่เป็น **ผลจำลอง ไม่ใช่ผลวิ่งจริง** แบบจำลองไม่รวมการไถล การสั่น และการหยุดแก้ทางของหุ่นจริง
ค่าเวลาชุดเต็มบนเว็บเป็นประมาณการ รวมการตั้งล้อ การรอ และขากลับ; สำหรับค่าชุดนี้ประมาณ 22 นาที
ผลเดโมเก่าระยะ 0.30 m ไม่ใช่หลักฐานของเส้นทาง 2 เมตรนี้

## ตั้งค่าและเริ่มจากเว็บ

1. เปิดเว็บด้วย `docker\mor_luam.bat web` หรือใช้ IP จาก `docker\mor_luam.bat find`
2. เมื่อหยุดหุ่นแล้ว ไป **ตั้งค่า → เดโมปุ่มบนหุ่น**:

   | ช่อง | ค่า |
   |---|---:|
   | ระยะทางขาไปเดโม 3 / 4 และทดสอบ 3 รอบ | 2.00 m |
   | แบ่งขาไปเป็นกี่ช่วง | 7 |
   | มุมเป้าเยื้องขวาจากล้อ | 6° |
   | ความเร็ววิ่ง | 0.03 m/s |
   | ความเร็วเลี้ยวที่ใช้วางแผน | 35°/s |

3. กด **บันทึกการตั้งค่า** กลับแท็บเส้นทาง กล่องเปรียบเทียบต้องแสดง `ขาไปรวม 2.00 m · 7 ช่วง`
4. ให้หุ่นอยู่บนพื้น ผู้ควบคุมอยู่ข้างหุ่น และตลอดเส้นทางไป–กลับไม่มีคน สายไฟ หรือสิ่งกีดขวาง
   ข้อความบนเว็บจะแสดงพื้นที่ตามระยะที่ตั้ง สำหรับชุดนี้อย่างน้อย 2.5 m ตามแนวทาง พร้อมพื้นที่ด้านข้าง
   ค่านี้เป็นระยะเผื่อสำหรับเตรียมพื้นที่ ไม่ใช่การรับรองว่าหุ่นจะไม่ออกนอกแนว
5. เมื่อพร้อม จึงติ๊กช่องยืนยันและกด **ทดสอบ 3 รอบ** ต้องเปิดหน้าเว็บไว้ตลอด
6. สังเกตล้อและหุ่นจริง หากต่างจากที่คาด ให้กด **หยุดชุดทดสอบ**, **E-STOP** หรือปุ่มบนหุ่น

เปลี่ยนระยะ/จำนวนช่วง/มุม/ความเร็วหลังติ๊กยืนยัน จะต้องยืนยันใหม่
ระหว่างชุดทดสอบ firmware ปฏิเสธการแก้ค่าชุดเปรียบเทียบเพื่อให้แต่ละคู่ใช้เงื่อนไขเดียวกัน
ไม่มีการเริ่มมอเตอร์อัตโนมัติจากการบันทึกค่าหรืออัปเดตเฟิร์มแวร์

ปุ่มจริง **3 ครั้ง = Direct**, **4 ครั้ง = Detour** ใช้เส้นทางเปรียบเทียบชุดเดียวกันนี้
ปุ่ม 1/2 ยังคงใช้เส้นทางที่บันทึกแยกไว้ ค่าเริ่มจากโรงงานยังเป็น 0.30 m / 1 ช่วง

## กดปุ่มแล้วเว็บโชว์ภาพไหม

- ปุ่ม **3/4**: กล่องเปรียบเทียบอัปเดตทางที่วัดได้ เส้นเวลาเลี้ยว/ขับ และเวลาที่ใช้ระหว่างวิ่ง
  เปิดเว็บภายหลังก็โหลดผลได้ จนกว่าหุ่นจะรีบูตหรือมี run ใหม่ของแบบเดียวกันมาแทน
- ปุ่ม **1/2**: ดูตำแหน่งและรอยทางสดบนระนาบหลัก ไม่เพิ่มผลในตาราง Direct/Detour
  รอยทางสดเก็บในหน้าเว็บ จึงควรเปิดเว็บระหว่างวิ่ง
- ทั้งสี่ปุ่มมีสถานะปุ่ม/การวิ่งบนเว็บ แต่การหยุดด้วยปุ่มจริงไม่ต้องพึ่งหน้าเว็บ

## อ่านผลและบันทึกรูป

- เส้นประ = แผนตามจุดของ run นั้น เส้นทึบ = odometry ที่หุ่นบันทึก ไม่ใช่ตำแหน่งจากเครื่องมือภายนอก
- จุดมีเลข 1–7 = จุดที่ต้องผ่าน วงลูกศร = จุดที่ล้อหมุนอยู่กับที่
- ดูเส้นเวลาหมุน/ขับและตารางรายรอบเพื่อเปรียบเทียบ ไม่สรุปผู้ชนะจากรูปเส้นทางอย่างเดียว
- เวลาจับบนหุ่นหลังตั้งล้อร่วมกันจนถึงจุดสุดท้าย ไม่รวมพัก 5 s ขากลับ และพักก่อน run ถัดไป
- ข้อมูลเก่าคงเงื่อนไขของ run เก่า การเปลี่ยนตั้งค่าไม่เปลี่ยนข้อมูลที่บันทึกแล้ว
- รูปจากข้อมูลจริง: `python tools/demo_compare_plot.py --series` หรือเพิ่ม `--wait` เพื่อรอชุดจบ

## สำหรับผู้พัฒนา

`demoDistM` คือระยะขาไปรวม 0.10–2.00 m; `demoSegments` คือจำนวนช่วง 1–7
และแต่ละช่วงต้องยาวอย่างน้อย 0.10 m เก็บจำนวนช่วงใน NVS key `dlegs`
อัปเดตแบบ partial ได้ที่ `POST /api/settings` โดยไม่ส่งรหัสผ่าน

`GET /api/status` ส่งเฉพาะค่าการเคลื่อนที่ที่จำเป็นใน `nav.demo` เพื่อให้เว็บแสดงระยะ/พื้นที่ได้ตามจริง
ผลเส้นทางและกิจกรรมแยกดาวน์โหลดทีละ run เพื่อหลีกเลี่ยง JSON ขนาดใหญ่บน ESP32:

| API | ข้อมูล |
|---|---|
| `/api/demo/compare` | สรุปผล Direct / Detour |
| `/api/demo/compare?run=0` / `?run=1` | รายละเอียด Direct / Detour รวม `xy`, `route`, `acts` |
| `/api/demo/series` | สรุปชุด 6 runs |
| `/api/demo/series?run=i` | รายละเอียด run ที่ i รวมทางที่วัด จุดที่ต้องผ่าน และกิจกรรม |

ทดสอบออฟไลน์: `docker\mor_luam.bat fw-test` และ `node firmware/web/test_route_test.cjs`
ชุด C++ ตรวจครบ 6 runs, 7 จุด, ระยะรวม 2 เมตร และการกลับจุดเริ่ม โดยไม่เชื่อมต่อหุ่น
การผ่านบนคอมไม่แทนการทดสอบบนพื้นจริง อ่าน [Safety](safety.md) ก่อนเริ่ม
