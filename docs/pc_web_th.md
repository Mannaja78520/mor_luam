# เว็บบนคอม: ไม่มีหุ่นก็วางจุดและจำลองได้

รันจากโฟลเดอร์โปรเจกต์บน Windows:

```powershell
docker\mor_luam.bat web
```

เปิด [http://localhost:8000/](http://localhost:8000/) เว็บทำงานจากไฟล์บนคอม ไม่ต้องเปิด Docker
เก็บ terminal นี้ไว้ระหว่างใช้เว็บ; Ctrl+C ปิด server บนคอม เรียก `web` อีกครั้งได้โดยไม่เปิด server ซ้ำ
Ubuntu ใช้ `./docker/mor_luam.sh web`; เรียกตรงด้วย `python tools/pc_web.py` ก็ได้

## ไม่มีหุ่น

หน้าเว็บเปิดได้ทันที แท็บ **จำลอง** ทำงานในเบราว์เซอร์:

1. แตะระนาบเพื่อเพิ่มจุด ลากจุดเพื่อย้าย หรือเลือกโหมด **ลบจุด** แล้วแตะจุด
2. ใส่ค่า x/y แล้วกด **เพิ่มจุดจำลอง** ได้ ถ้าต้องการพิกัดแม่นยำ
3. กด **จำลองจุดที่วาง** ดู Direct และ Detour ใช้จุดชุดเดียวกัน
4. **ตัวอย่างอ้อม 0.3 m / 6°** และ **ตัวอย่างรวม 2 m / 7 ช่วง** โหลดจุดไว้ลองได้
5. **คัดลอกจากเส้นทางที่เลือก** คัดลอกจุดจากแท็บเส้นทางเมื่อเคยโหลดได้ แต่การแก้จุดจำลองไม่แก้จุดต้นฉบับ

เริ่มจำลองที่ (0,0) ล้อชี้ +x; +y คือซ้ายของหุ่น มุมเพิ่มทวนเข็ม
จุดจำลองแยกจากเส้นทางจริง บันทึกเป็นข้อมูลของเบราว์เซอร์ ไม่ส่ง API สั่งมอเตอร์หรือบันทึกจุดลงหุ่น
ตัวเลขในผลจำลองเป็นค่าของแบบจำลอง ไม่ใช่ข้อมูลสดจากหุ่น

## เมื่อเปิดหุ่น

ให้หุ่นกับคอมอยู่ Wi-Fi วงเดียวกัน (เช่น Wi-Fi บ้าน, Hotspot มือถือ, หรือ Hotspot คอมพิวเตอร์) server จะค้นหา `mor-luam.local`
และสแกนค้นหาทุก subnet ของคอมพิวเตอร์ให้อัตโนมัติ แล้วเชื่อมต่อให้ทันทีโดยไม่ต้องระบุ subnet
เมื่อหุ่นตอบ เว็บแสดง **เชื่อมหุ่นจริง + IP** และโหลดสถานะ/จุด/การตั้งค่าใหม่
การเชื่อมต่อหรือเปิดหน้าเว็บ **ไม่เริ่มมอเตอร์เอง** ต้องเริ่มจากปุ่มจริงหรือคำสั่งของผู้ควบคุม

หุ่นดับหรือหลุด: เว็บยังเปิดอยู่และจำลองได้ ปุ่มควบคุมจริงใช้ไม่ได้จนกว่าจะเชื่อมใหม่
คำสั่งที่ถูกปฏิเสธขณะ offline ไม่ถูกเก็บไว้สั่งย้อนหลังเมื่อหุ่นกลับมา

ถ้าคำขออ่านข้อมูลหล่น server ลอง GET ซ้ำได้หนึ่งครั้ง ส่วน POST สั่งมอเตอร์/ตั้งค่าจะไม่ส่งซ้ำอัตโนมัติ เพราะหุ่นอาจรับคำสั่งไปแล้วแต่คำตอบหาย หลายแท็บที่รอสถานะพร้อมกันใช้ผลจากคำขอสดเดียวกัน ไม่ส่งคำขอสถานะซ้อนกันลงหุ่น

server ไม่ส่ง heartbeat เอง การค้นหาพื้นหลังใช้เฉพาะ `GET /api/whoami`
heartbeat/status ที่คงการวิ่งมาจากหน้าเว็บที่เปิดอยู่เท่านั้น
คำสั่งหยุดมีลำดับก่อนการดาวน์โหลดข้อมูลทั่วไป แต่การหยุดผ่านเครือข่ายยังต้องพึ่งการเชื่อมต่อที่ทำงาน

## ใช้ชื่อ mor-luam.local ได้ไหม

| URL / คำสั่ง | เว็บอยู่ที่ไหน | ต้องมีหุ่น |
|---|---|---|
| `http://localhost:8000/` / `web` | คอมเครื่องนี้ | จำลองไม่ต้องมี; ควบคุมจริงต้องเชื่อม |
| `http://mor-luam.local/` / `web-robot` | ESP32 บนหุ่น | ต้องเปิดหุ่นและเข้าถึงเครือข่าย |
| `web-mock` | หุ่นสมมติสำหรับพัฒนาบนคอม | ไม่มีการเชื่อมหุ่นจริง |

ไม่ผูก `mor-luam.local` กลับไปที่คอม เพราะชื่อนี้เป็นของหุ่นและตัวช่วย OTA/ค้นหาก็ใช้ชื่อนี้
`localhost` ใช้เฉพาะเครื่องที่รัน server; URL นี้ไม่ได้เปิดให้เครื่องอื่นใน Wi-Fi เข้ามาควบคุม

## ตัวเลือกและแก้ปัญหา

```powershell
docker\mor_luam.bat web --port 8001
python tools/pc_web.py --host mor-luam.local --port 8000
```

- พอร์ต 8000 ถูก `web-mock` หรือโปรแกรมอื่นใช้: ปิดโปรแกรมนั้น หรือใช้พอร์ต 8001
- เว็บขึ้นแต่หุ่นไม่เชื่อม: ตรวจไฟ ESP32, Wi-Fi, `docker\mor_luam.bat find` และ IP ที่เปลี่ยนได้
- ถ้าหุ่นไม่ตอบ API แม้ Wi-Fi แสดงเชื่อม ต้องตรวจบอร์ด/การเชื่อมต่อจริง; server บนคอมไม่สร้างสถานะหุ่นปลอมมาทดแทน
- OTA ใช้ `docker\mor_luam.bat fw-ota` หรือหน้าเว็บตรงบนหุ่นขณะหยุด ไม่ส่ง firmware ผ่านคิวควบคุมของ server บนคอม
- อ่าน [ความปลอดภัย](safety.md) ก่อนขยับจริง และ [เปรียบเทียบ 2 เมตร](compare_2m_th.md) สำหรับชุด 7 ช่วง

ทดสอบแบบไม่ใช้ฮาร์ดแวร์: `python tools/test_pc_web.py` (7 กรณี รวมตรวจ subnet ท้องถิ่น, GET retry, จัดการ HTTP 200 ว่างเปล่า, POST ไม่ซ้ำ และหลายแท็บใช้คำขอสถานะร่วมกัน), `node firmware/web/test_api.cjs` (ตรวจการปฏิเสธ JSON ว่าง/ไม่สมบูรณ์) และ `node firmware/web/test_simulation_route.cjs`
